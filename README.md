# nest

Менеджер бэкапов для папок. `nest` запоминает связи «источник → папка бэкапа», умеет
синхронизировать их, показывать изменения и разворачивать бэкапы обратно на новом
компьютере.

> Проект находится в бета-версии. Обратная совместимость форматов файлов не гарантируется.

## Возможности

- Бэкап папок (сравнение по размеру и времени изменения файлов)
- Просмотр изменений без записи на диск (`diff`)
- Таблица состояния всех бэкапов (`status`)
- Развёртывание бэкапов обратно в источники (`deploy`), в том числе на чистую систему
- Глобальный список папок, где инициализирован `nest` (`where`)

## Установка

Требуется Rust (edition 2024).

```bash
git clone <https://github.com/xterra144-hub/nest.git>
cd nest
cargo build --release
```

Бинарник появится в `target/release/nest`. Для установки в `PATH`:

```bash
cargo install --path .
```

## Быстрый старт

```bash
# 1. Инициализировать nest в папке (создаст nest_backup_jornal.toml)
nest init ~/dots

# 2. Добавить связь: источник ~/dots → бэкап ~/backups/dots
nest add ~/dots ~/backups/dots --name dots

# 3. Посмотреть, что изменилось
nest --dir ~/dots diff

# 4. Синхронизировать
nest --dir ~/dots sync
```

## Команды

Глобальный флаг `--dir <path>` задаёт папку, в которой лежит `nest_backup_jornal.toml`.
По умолчанию используется текущая папка. Флаг можно указывать до или после подкоманды:

```bash
nest --dir ~/dots sync
nest sync --dir ~/dots
```

### `nest init <folder>`

Создаёт в указанной папке файл `nest_backup_jornal.toml` и регистрирует папку в
глобальном конфиге `nest`.

- Папка должна существовать.
- Если конфиг в папке уже есть, но папка не зарегистрирована глобально, она будет
  добавлена, и команда выведет `added <path> to config`.
- Если всё уже было — выводится ошибка `nest already initialized in <path>`.

```bash
nest init ~/dots
```

### `nest add <source> <backup_dir> --name <name>`

Добавляет связь между папкой-источником и папкой бэкапа.

- Оба пути должны существовать и быть папками.
- Имя (`--name`) должно быть уникальным в пределах конфига.
- Пути сохраняются абсолютными.

```bash
nest add ~/dots ~/backups/dots --name dots
```

### `nest remove <name>`

Удаляет связь по имени из конфига. Сами файлы не трогаются.

```bash
nest --dir ~/dots remove dots
```

### `nest diff`

Строит список действий (`source` → `backup_dir`), ничего не изменяя на диске.

```bash
nest --dir ~/dots diff
```

Пример вывода:

```
'dots': 3 changes
  + dir      /home/user/backups/dots/nvim
  + new      /home/user/backups/dots/.bashrc
  ~ changed  /home/user/backups/dots/.config/fish/config.fish
```

### `nest sync`

Применяет изменения: копирует новые и изменённые файлы из источника в папку бэкапа,
создаёт недостающие папки и обновляет `last_backup` в конфиге.

```bash
nest --dir ~/dots sync
```

Правила сравнения файлов:

- файла нет в бэкапе → `new`;
- размер отличается или время изменения источника новее → `changed`;
- иначе файл считается актуальным и не копируется.

Символические ссылки пропускаются.

### `nest status`

Показывает таблицу со всеми связями: имя, источник, папку бэкапа, дату последней
синхронизации и признак необходимости синхронизации.

```bash
nest --dir ~/dots status
```

### `nest deploy [--force]`

Обратная операция к `sync`: копирует файлы из `backup_dir` в `source`.
Если источника не существует, он создаётся.

Перед развёртыванием проверяется целостность: верхний уровень `backup_dir` должен
соответствовать записям в `nest_backup_jornal.toml`. Если в папке бэкапа есть
каталог, которого нет в конфиге, команда завершится ошибкой.

Режимы:

- **Без `--force`** — безопасный: копируются только отсутствующие в источнике файлы,
  существующие не изменяются.
- **С `--force`** — источник удаляется полностью и копируется заново из бэкапа.

```bash
# Перенести бэкап на чистую систему, не трогая существующие файлы
nest --dir ~/dots deploy

# Полностью заменить источник содержимым бэкапа
nest --dir ~/dots deploy --force
```

Типичный сценарий переноса дотфайлов на другой компьютер:

1. Скопировать папку с бэкапами и `nest_backup_jornal.toml` на новую машину.
2. При необходимости поправить пути в `nest_backup_jornal.toml`.
3. Выполнить `nest --dir <папка с конфигом> deploy`.

### `nest where`

Выводит список всех папок, где был выполнен `nest init`, по одной на строку.
Работает из любой директории.

```bash
nest where
```

```
/home/user/dots
/home/user/nvim
```

## Файлы конфигурации

### Локальный конфиг `nest_backup_jornal.toml`

Хранится в папке, где выполнен `nest init`. Пример:

```toml
[[backups]]
name = "dots"
source = "/home/user/dots"
backup_dir = "/home/user/backups/dots"
last_backup = "2026-10-23T18:00:00+03:00"

[[backups]]
name = "nvim"
source = "/home/user/.config/nvim"
backup_dir = "/home/user/backups/nvim"
last_backup = "2026-10-23T18:00:00+03:00"
```

Поля:

| Поле          | Описание                                      |
|---------------|-----------------------------------------------|
| `name`        | Уникальное имя связи                          |
| `source`      | Абсолютный путь к папке-источнику             |
| `backup_dir`  | Абсолютный путь к папке бэкапа                |
| `last_backup` | Время последней синхронизации (RFC 3339)      |

### Глобальный конфиг

Путь: `$XDG_CONFIG_HOME/nest/config.toml` или `~/.config/nest/config.toml`,
если `XDG_CONFIG_HOME` не задан.

```toml
projects = [
    "/home/user/dots",
    "/home/user/nvim",
]
```

Файл создаётся автоматически при первом `nest init`.

## Ограничения

- Работа поддерживается только с папками: `source` и `backup_dir` должны быть
  директориями.
- Символические ссылки при синхронизации пропускаются.
- Для `deploy` папка бэкапа должна существовать; при отсутствии — ошибка.
- `deploy` не изменяет `last_backup` в конфиге.
- Сравнение файлов не использует хеши: учитываются размер и время изменения.
